## 自动调整与提示

通过单独的临时测试 APK 调用相机实际 CameraEx 参数接口，逐项写入并读回确认，再释放接口、从正常 LUT 库进入未经注入的产品拍摄页。每项结束恢复基线。测试工具不调用快门、显影或保存接口，未修改固件；原始日志与工具源码均保存在忽略目录。

rc.6 自动调整 RAW／连拍等成功时缺少明确说明。rc.7 在完成参数设置、读回和拍摄初始化后显示实际调整内容，持续 10 秒，并说明“仅本次拍摄生效，退出后恢复”。不增加确认步骤，不拦截快门。HDR 错误页保留 MENU 返回路径，返回 LUT 库后还会显示同一错误说明。

RAW 提示已取得真机截图并检查排版；其他正常路径有屏幕更新事件及前台状态记录。后续系统截屏接口返回空图，同时 WindowManager 报告截图失败，因此没有把空图计为视觉验收；HDR 绘画的实际显示由用户现场确认。

## 恢复与验证

每项正常会话均进入可拍状态并通过 MENU 返回；产品日志记录曝光、画质和拍摄设置恢复读回一致。HDR 绘画由用户确认错误页后，通过 MENU 返回 LUT 库。临时工具将测试开始前保存的设置恢复并读回确认。

主机产品测试（含新增提示契约）、旧机兼容回归、发行 APK 的 DEX035/API10/ARM/资源检查通过。新提示仅根据设置前后实际读回差异生成；未成功切换或缺少原值时不会声称已调整。公开 Release 仍为 beta.5。

## 原生菜单自动 HDR

用户从原生菜单开启自动 HDR 并重新打开测试连接。正式复测时，产品实际读到 `hdr=auto effect=off`，在参数配置前拦截，记录 `capture HDR enabled: hdr-mode=auto picture-effect=off`；持续保持 PhotoActivity 前台错误页，CameraEx 正常释放，没有退出或重启。用户确认原生自动 HDR 的提示文字清楚，并将原生设置恢复为测试前的 DRO 自动。随后复查实际读到 `hdr=off effect=off`，正常进入待拍；MENU 返回 LUT 库，曝光、画质、变焦和拍摄设置均恢复成功，boot ID 始终不变。**本轮设置兼容验收通过。**

首次尝试中的“退出应用”已查清是测试脚本误操作：LibraryActivity 恢复了旧的 `options selection=3`（退出应用），脚本错误地接受同一进程历史上的 `page_ready mode=library`，随后按中央键执行正常退出。恢复的日志完整记录了 `native_exit_check_ipc → native_exit_prepare_debug_link → native_exit_requested`，这一尝试没有新拍摄会话，不能计为 HDR 崩溃。已将脚本改为核对最新页面状态、明确返回 LUT 库后才按中央键；复测增加实时落盘日志和启动时间下限，避免复用历史会话。
