# 用户故障日志

从 **0.9.0-beta.6-rc.8 / code104** 开始，普通发行包默认记录应用自己的诊断信息。无需调试连接、ADB、Root 或预先开启开关；不上传到服务器。

## 用户怎么提供日志

1. 出现问题后，记下屏幕现象和刚才的操作。如果应用退出，重新打开 LUT Camera。
2. 在 LUT 库按 **MENU → 导出诊断日志**。
3. rc.9 起导出后仍停留在“更多”菜单原选项，上下键可继续翻页，MENU 返回 LUT 库。看到“日志包已导出”后，用读卡器从 SD 卡取出 **`SONYLUT/DIAG/REPORT.ZIP`**，连同复现步骤发给开发者。重复导出时，上一份保留为 `PREV.ZIP`。

如果应用连 LUT 库都打不开，错误提示页也有“导出诊断日志”入口。如果 SD 卡不可写，先解决写保护或空间问题再导出；机身内的最近记录会一并打包。无法再打开应用时，可以直接提供 SD 卡上的 `SONYLUT/DIAG/LOGS/` 文件夹。

日志不打包照片、LUT 文件、系统 logcat 或网络凭据，不主动查询序列号。异常文本可能包含文件名，发送前可解压查看。

## 记录范围

- 应用版本、机型、Sony 固件/平台、Android/API/ABI、堆上限、可用存储；未提供的 Sony 属性明确标为 unavailable。
- 每个进程的随机会话号、启动标识、时间与单调时钟。相机日期未设置时按同一启动内的 uptime 排序。
- 菜单与生命周期、所选 LUT 的内容摘要和阶数、拟合、相机打开、参数能力、HDR/格式/画质/尺寸、预览与内存布局。
- 拍摄、显影、完整 LUT 计算、保存通知、下一张待拍、参数恢复、正常退出。
- 可捕获 Java 错误及有限堆栈；拍摄进程异常返回时保留库页面的中断记录。

原生进程突然结束时保留此前已写入的阶段，不承诺取得 native 堆栈。只有缺少 `closed` 时，应判断为“未记录正常结束”，再结合用户现象分析，不能直接认定崩溃。

## 存储与性能

机身应用私有目录和 SD 卡 `SONYLUT/DIAG/LOGS/` 各一套滚动记录：`UI0–1.TXT`、`CAP0–5.TXT`，每段上限 64 KiB，每处最多 512 KiB。启动和超限时轮转，保留最近记录；新一次重试不会立即覆盖上一轮拍摄故障。卸载会删除机身私有记录，滚动历史也不会永久保留，应在出问题后尽快导出。

日志采用小块追加写入，关键边界同步落盘；采集写入失败不向拍摄流程抛异常。SD 失败时保留机身记录，导出的 SUMMARY 会注明失效的写入端。没有周期性系统日志抓取，也不在日志里复制图像数据。生产拍摄不再为每次进入创建无上限的 `SONYLUT/Rxxxxxxx/PROBE.JSN` 目录；原有历史文件保留，开发诊断入口仍沿用自身记录。

Sony SD 文件系统拒绝同时读写同一日志文件（EBUSY）。导出在进程锁内关闭写入端，打包后按追加方式恢复，既不清空当前文件，也不让事件写入与打包交叉。日志包只收集固定文件名，校验 ZIP 目录、各成员与 CRC 后才替换 REPORT.ZIP；失败保留上一份完整报告。

## 开发者分析

```sh
python3 scripts/analyze_diagnostics.py /path/to/REPORT.ZIP
python3 scripts/analyze_diagnostics.py /path/to/REPORT.ZIP --json
```

解析器不解压或执行内容，检查成员名、数量与大小上限，以 `session + seq` 去除机身/SD 镜像重复事件，列出机型、会话末尾、错误和保存关键事件；截断行单独计数。查看 JSON 原始记录可进一步定位阶段和参数。

主机验证：`bash scripts/test_product_ui.sh`、`python3 scripts/test_diagnostics_analyzer.py`。设备验证记录保存在本地忽略目录 `results/support-diagnostics-20261101/`。
