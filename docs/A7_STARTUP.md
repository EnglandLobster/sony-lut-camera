# A6000 / A7 一代准备拍摄失败：旧接口兼容修复

候选版本：**0.9.0-beta.6-rc.6 / code102**。保留公开 beta.5 的包名与签名，可覆盖安装。公开发行仍为 beta.5，候选源码位于 `fix/a7-capture-startup`。

## 已确认的启动阻断点

从 Sony 官方 A6000 3.21、A7 3.20 固件提取的 CameraEx 中，都不存在 `StoreImageCompleteListener` 和对应 setter。beta.5 在 `registerCameraListeners()` 强制查找该接口，位置就在打开相机之后、开始预览之前，因此会抛出 `ClassNotFoundException`，关闭会话，无法进入拍摄。这个问题与所选 LUT 无关。

rc.4 按实际接口选择保存协议：

- 有新版保存回调的机型：保持按回调提供的文件名确认保存。
- 老机型：复用 Sony 媒体索引，保存前记录序号，等待唯一的新索引记录与稳定、完整的新 JPEG 对应后才继续。原片确认后才改动显影图像、应用完整 LUT，再保存独立成片。旧机关闭保存／调色重叠优化，保持分辨率与完整 LUT；JPEG 使用机型实际支持的最高已知档位，界面显示真实档位。

没有启用旧 `JpegListener`：固件反汇编显示它经过整张 JPEG 数据回调，增加老机 24 MB Java 堆的压力。索引确认不把整张 JPEG 复制进 Java 堆。

## 用户反馈补充与 rc.6

用户报告 A6000 的 Surface 已触发生命周期回调，但 `isValid()` 始终为 false，以及 JPEG 能力仅有 `50,25`。此前通用模拟器测试未覆盖这两个实机条件；rc.5 中这两个守卫仍可能阻断拍摄。

rc.6 以 `surfaceCreated/surfaceChanged` 为就绪依据，不再拿 Android Surface 的 isValid 标志阻止 Sony 拍摄。LUT 准备、Activity 恢复和 Surface 回调的先后顺序都可触发一次初始化；重复回调不会重复打开相机。准备阶段 Surface 重建会等待新界面；缺少回调每 250 ms 重查，5 秒后显示“取景界面尚未就绪”。启动后的 Surface 丢失也显示原因。

JPEG 档位由实际能力选择，`50,25` 选择 FINE，包含 95 时选择 EXTRA FINE；初始化读回、RAW 注册后检查和下一张拍摄都使用同一个已选值。取景信息栏显示真实档位，库页面不再固定宣称 EXTRA FINE。原片和成片沿用同一档位，完整 LUT 与 6000×4000 不变。

反馈中的单张/JPEG 条件已由会话配置处理；数字变焦仍自动关闭并恢复；缺少新版保存回调使用媒体索引确认，不是整个应用无法适配的硬边界。

## 同时保留的修复

- 会话内临时配置单张、JPEG、6000×4000，验证读回并在退出时恢复用户原设置。
- 兼容老版 `libcameraseq.so` 缺少 `getPhysicalMemoryInfo` 的情况，使用其公开属性接口取得地址和长度，继续零拷贝处理。
- 显示初始化成功后才启动后台准备，避免失败后继续初始化、覆盖首个错误。
- 错误页显示中文原因和诊断路径，MENU 返回后保留完整错误说明；修正多行文字重叠。

## 通用设置提示（rc.5，包含 A6300）

RAW／RAW+JPEG、非单张和非 6000×4000：应用尝试临时切换到单张 JPEG／24MP；非 P 模式：尝试设置 P 自动曝光、自动 ISO；画质：在固件广告的档位中优先选择 EXTRA FINE，其次 FINE、STANDARD。正常退出恢复原设置。失败页按具体字段给出手动设置方法，包含 3:2、L（24M）、JPEG、P 档／ISO 自动、额外精细，而非只要求用户“检查设置”。

自动 HDR（on/auto）或 HDR 绘画会在配置拍摄参数前被拦截，提示 MENU 返回并退出应用，到原生菜单关闭 HDR。没有静默改动 HDR 或开始拍摄。

拍摄 Activity 异常结束、返回 LUT 库时，会弹出“拍摄会话意外结束”和重试／诊断方法。正常按 MENU 返回与已有的具体错误返回分开处理。若相机系统结束了整个应用，库页面也不会继续运行，这不属于 Activity 返回提示能覆盖的路径。

## 验证结果

两份官方固件的 47 个其他必需 Java 方法均存在，旧版媒体索引 URI、DCF 文件编号与保存顺序字段存在。API10 / 24 MB 堆 ARM 模拟器通过全部 10 个内置 LUT 的原生初始化和回看缓冲测试，以及旧接口缺失、兼容协议选择、双文件确认、索引未就绪、重复／过期结果、取消、超时、歧义拒绝测试。现代回调路径也有回归测试。

两份原生库的旧内存属性函数均用真实 ARM 指令仿真通过。发行包构建和 API10/DEX035/ARM/v1 签名检查通过。详细证据、脚本和验证范围见 [离线研究记录](LEGACY_OFFLINE_VALIDATION.md)。本轮没有连接真机，物理快门与实际 SD 保存仍未实机验收。

## 现场诊断

若候选包仍出现错误，屏幕会显示原因。诊断文件为 SD 卡 `SONYLUT/DIAG/INIT.TXT`，记录最后完成的阶段、平台、相机设置和异常；下一次进入拍摄会覆盖该文件。文件不包含照片、序列号或网络密码。
